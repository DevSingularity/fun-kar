## Stated assumptions (safest production-grade defaults)

1. **Module-per-engine layout, as you specified** — every business engine gets its own folder under `modules/` (auth now; quotation, risk, approval, fulfillment, billing, negotiation, dealhealth, recommendation in later phases). No shared "resource" template — the existing generic `resourceItems`/`resource.*` scaffold is dead code and should be deleted.
2. **`users` table has no refresh-token/session column**, and no `refresh_sessions` table exists anywhere in the schema or in Phase 1's scope. Building one isn't asked for, so refresh tokens are **fully stateless JWTs** (signature + expiry only, no server-side revocation) for this phase. Logout is a client-side cookie clear. This is a known MVP gap to revisit in Phase 9 (Hardening) if a sessions table is added later.
3. **Public self-signup only ever creates `SALES_REP`.** Letting `/register` pick any role (including `ADMIN`) would be a privilege-escalation hole. `ADMIN` / `SALES_MANAGER` / `FINANCE` / `OPERATIONS` accounts are created by seed script now, and by an Admin-only "create internal user" endpoint in Phase 2.
4. **`CUSTOMER` portal auth (`customer_users`, `portal_tokens`) is out of scope for Phase 1.** The schema comment on `users.js` itself says customers use a separate trust boundary, and the portal experience is Phase 7. Building it now would violate "don't invent requirements ahead of plan.md."
5. **Demo-account selector** exposes only a fixed allow-listed set of `{role, name, email}` read from env config (never a live query over real user rows), gated behind `ENABLE_DEMO_ACCOUNTS=true`, and returns a single shared demo password only in that mode — never real password hashes.
6. Response/error envelope is standardized now (`{success, data}` / `{success, error}`) since `plan.md` explicitly requires "consistent API response/error format" — this replaces the generic `{message}` shape in the current template's `error.middleware.js`.

## API Specifications — Auth Module

### 1. `POST /api/v1/auth/register`
- **Purpose:** Self-service signup for internal staff. Always creates a `SALES_REP` (see assumption 3).
- **Auth:** None (public). Rate-limited.
- **Body:** `{ name, email, password, confirmPassword }`
- **Validation:** `name` 1–150 chars trimmed; `email` RFC-shaped, ≤255, lower-cased; `password` ≥8 chars, ≥1 letter + ≥1 digit; `confirmPassword === password`. Reject any `role` field in body (ignored, not just unused).
- **Idempotency:** Natural, via `users_email_lower_unique`. A retried identical request after a prior success returns `409 EMAIL_TAKEN`, never a duplicate row.
- **Transaction boundary:** `INSERT INTO users` + `INSERT INTO audit_logs (entityType='USER', action='REGISTER')` in one DB transaction — both succeed or neither does.
- **DB operations:** `SELECT 1 FROM users WHERE lower(email)=:email` (pre-check, best-effort) → `INSERT INTO users (...)` inside txn → `INSERT INTO audit_logs (...)` inside txn.
- **Concurrency:** Two concurrent identical signups race past the pre-check; the unique index is the real guard — catch Postgres `23505`, roll back txn, map to `409`.
- **Rollback:** Automatic txn rollback on unique-violation or any insert failure — no orphaned user without an audit trail, or vice versa.
- **External services:** None (no email verification in Phase 1 — noted MVP gap).
- **Success:** `201` `{ success:true, data:{ user:{id,name,email,role,isActive,createdAt}, accessToken, refreshToken } }`
- **Errors:** `400 VALIDATION_FAILED`, `409 EMAIL_TAKEN`, `429 TOO_MANY_REQUESTS`, `500 INTERNAL_ERROR`
- **Performance:** Single indexed lookup + single indexed insert; bcrypt cost 12 (async, off event-loop-blocking path via libuv threadpool).

### 2. `POST /api/v1/auth/login`
- **Purpose:** Authenticate any internal staff member, any role.
- **Auth:** None (public). Rate-limited (brute-force protection).
- **Body:** `{ email, password }`
- **Validation:** valid email shape; password non-empty.
- **Idempotency:** Naturally idempotent — pure read + token issuance, no row mutation.
- **Transaction:** Not required — single read.
- **DB operations:** `SELECT * FROM users WHERE lower(email)=:email`.
- **Concurrency:** None (read-only).
- **Rollback:** N/A.
- **Success:** `200` `{ success:true, data:{ user, accessToken, refreshToken } }`
- **Errors:** `400 VALIDATION_FAILED`; `401 INVALID_CREDENTIALS` (generic — used both for unknown email and wrong password, to avoid user enumeration); `403 ACCOUNT_DISABLED` (`isActive=false`); `429`; `500`.
- **Performance:** Single indexed lookup on `users_email_lower_unique`.

### 3. `POST /api/v1/auth/refresh`
- **Purpose:** Issue a new access+refresh pair from a still-valid refresh token.
- **Auth:** Valid, unexpired refresh JWT — httpOnly cookie preferred, JSON body fallback for non-browser demo clients.
- **Validation:** token present; `jwt.verify` passes; `decoded.type === 'refresh'`.
- **Idempotency:** Safe to call repeatedly before expiry (stateless — no double-spend protection in this phase, per assumption 2).
- **Transaction:** None — one read to reconfirm the account is still active before reissuing.
- **DB operations:** `SELECT id, role, isActive FROM users WHERE id=:decoded.userId`.
- **Concurrency:** None.
- **Success:** `200` `{ success:true, data:{ accessToken, refreshToken } }` (+ re-set httpOnly cookie).
- **Errors:** `401 INVALID_REFRESH_TOKEN`, `401 REFRESH_TOKEN_EXPIRED`, `403 ACCOUNT_DISABLED`, `404 USER_NOT_FOUND`.
- **Performance:** PK lookup, O(1).

### 4. `POST /api/v1/auth/logout`
- **Purpose:** End the client session (clear refresh cookie). No server-side state to mutate under the stateless model.
- **Auth:** None strictly required; accepts whatever cookie/token is present and clears it regardless.
- **Idempotency:** Trivially idempotent.
- **Success:** `200` `{ success:true, data:{ loggedOut:true } }`, `Set-Cookie` with immediate expiry.
- **Note:** True server-side revocation needs a sessions table — flagged for Phase 9.

### 5. `GET /api/v1/auth/me`
- **Purpose:** Return the authenticated user's own profile.
- **Auth:** Required — Bearer access token via `authenticate` middleware.
- **DB operations:** `SELECT id,name,email,role,isActive,createdAt,updatedAt FROM users WHERE id=req.auth.userId` (passwordHash never selected).
- **Success:** `200` `{ success:true, data:{ user } }`
- **Errors:** `401 UNAUTHENTICATED`, `403 ACCOUNT_DISABLED`, `404 USER_NOT_FOUND` (deleted after token issuance).
- **Performance:** PK lookup.

### 6. `GET /api/v1/auth/demo-accounts` (bonus, `plan.md` §3)
- **Purpose:** Power the one-click demo login selector.
- **Auth:** Public, but gated: `404 NOT_FOUND` unless `ENABLE_DEMO_ACCOUNTS=true`.
- **DB operations:** None — reads a fixed `role → {name,email}` map from env/config (assumption 5), never a live `SELECT *` over real users.
- **Success:** `200` `{ success:true, data:{ accounts:[{role,name,email}], demoPassword } }` — `demoPassword` only ever present in this gated mode.
- **Errors:** `404` when disabled.

```
MODULE jwt.util
IMPORT env FROM '../config/env.js'

FUNCTION signAccessToken(user):
    RETURN jwt.sign(
        { userId: user.id, role: user.role, type: 'access' },
        env.jwtSecret,
        { expiresIn: env.accessTtl }
    )

FUNCTION signRefreshToken(user):
    RETURN jwt.sign(
        { userId: user.id, type: 'refresh' },
        env.jwtSecret,
        { expiresIn: env.refreshTtl }
    )

FUNCTION verify(token):
    TRY: RETURN jwt.verify(token, env.jwtSecret)
    CATCH e:
        IF e.name == 'TokenExpiredError': THROW UnauthenticatedError('Token expired.')
        THROW UnauthenticatedError('Token is invalid.')

FUNCTION buildTokenPair(user):
    RETURN { accessToken: signAccessToken(user), refreshToken: signRefreshToken(user) }
```

```
MODULE authenticate.middleware
IMPORT { verify } FROM '../common/jwt.util.js'
IMPORT { UnauthenticatedError } FROM '../common/errors.js'

FUNCTION authenticate(req, res, next):
    header = req.headers.authorization OR ''
    token = header.startsWith('Bearer ') ? header.slice(7) : req.cookies?.accessToken
    IF NOT token: RETURN next(UnauthenticatedError('Access token is required.'))

    decoded = verify(token)          // throws on invalid/expired -> caught by asyncHandler/global handler
    IF decoded.type != 'access': RETURN next(UnauthenticatedError('Invalid token type.'))

    req.auth = { userId: decoded.userId, role: decoded.role }
    next()
```

```
MODULE auth.validator

FUNCTION validateRegister(body):
    errors = []
    name = trim(body.name)
    email = lower(trim(body.email))
    password = body.password OR ''
    IF name.length NOT IN [1,150]: errors.push('Name is required (max 150 chars).')
    IF NOT isValidEmailShape(email) OR email.length > 255: errors.push('A valid email is required.')
    IF password.length < 8 OR NOT (hasLetter(password) AND hasDigit(password)):
        errors.push('Password must be at least 8 characters with a letter and a number.')
    IF body.confirmPassword != password: errors.push('Passwords do not match.')
    RETURN { valid: errors.empty, errors, clean: { name, email, password } }

FUNCTION validateLogin(body):
    errors = []
    email = lower(trim(body.email))
    IF NOT isValidEmailShape(email): errors.push('A valid email is required.')
    IF NOT body.password: errors.push('Password is required.')
    RETURN { valid: errors.empty, errors, clean: { email, password: body.password } }
```

**File: `server/src/modules/auth/auth.repository.js`**
```
MODULE auth.repository
IMPORT { getDb } FROM '../../config/database.js'
IMPORT { users, auditLogs } FROM '../../db/schema/index.js'
IMPORT { eq, sql } FROM 'drizzle-orm'

FUNCTION findByEmail(email):
    db = getDb()
    RETURN db.select().from(users).where(eq(sql`lower(${users.email})`, email)).limit(1).first()

FUNCTION findById(id):
    db = getDb()
    RETURN db.select({ id, name, email, role, isActive, createdAt, updatedAt })
             .from(users).where(eq(users.id, id)).limit(1).first()

// Runs INSERT user + INSERT audit_log atomically.
FUNCTION createInternalUser({ name, email, passwordHash, role = 'SALES_REP' }):
    db = getDb()
    RETURN db.transaction(async (tx) => {
        TRY:
            [user] = await tx.insert(users)
                .values({ name, email, passwordHash, role, isActive: true })
                .returning()
        CATCH e:
            IF e.code == '23505' (unique_violation on users_email_lower_unique):
                THROW ConflictError('EMAIL_TAKEN', 'An account with this email already exists.')
            THROW e
        await tx.insert(auditLogs).values({
            actorId: user.id, entityType: 'USER', entityId: user.id,
            action: 'REGISTER', newValue: { email: user.email, role: user.role }
        })
        RETURN user
    })
    // tx auto-rollback on any thrown error inside the callback
```

```
MODULE auth.service
IMPORT * as repo FROM './auth.repository.js'
IMPORT { hash, compare } FROM '../../common/password.util.js'
IMPORT { buildTokenPair, verify } FROM '../../common/jwt.util.js'
IMPORT { UnauthenticatedError, ForbiddenError, NotFoundError } FROM '../../common/errors.js'
IMPORT { env } FROM '../../config/env.js'

FUNCTION sanitize(user):
    RETURN { id, name, email, role, isActive, createdAt, updatedAt } // never passwordHash

FUNCTION register({ name, email, password }):
    passwordHash = await hash(password)
    user = await repo.createInternalUser({ name, email, passwordHash, role: 'SALES_REP' })
        // role is hard-pinned server-side; any 'role' sent by client is ignored upstream in validator
    tokens = buildTokenPair(user)
    RETURN { user: sanitize(user), ...tokens }

FUNCTION login({ email, password }):
    user = await repo.findByEmail(email)
    IF NOT user: THROW UnauthenticatedError('Invalid email or password.')   // generic — no enumeration
    ok = await compare(password, user.passwordHash)
    IF NOT ok: THROW UnauthenticatedError('Invalid email or password.')
    IF NOT user.isActive: THROW ForbiddenError('Account is disabled.')
    tokens = buildTokenPair(user)
    RETURN { user: sanitize(user), ...tokens }

FUNCTION refresh(refreshToken):
    IF NOT refreshToken: THROW UnauthenticatedError('Refresh token is required.')
    decoded = verify(refreshToken)                     // throws on bad sig/expiry
    IF decoded.type != 'refresh': THROW UnauthenticatedError('Invalid token type.')
    user = await repo.findById(decoded.userId)
    IF NOT user: THROW NotFoundError('User')
    IF NOT user.isActive: THROW ForbiddenError('Account is disabled.')
    RETURN buildTokenPair(user)

FUNCTION me(userId):
    user = await repo.findById(userId)
    IF NOT user: THROW NotFoundError('User')
    IF NOT user.isActive: THROW ForbiddenError('Account is disabled.')
    RETURN { user: sanitize(user) }

FUNCTION demoAccounts():
    IF NOT env.enableDemoAccounts: THROW NotFoundError('Route')
    RETURN { accounts: env.demoAccounts, demoPassword: env.demoPassword }
    // env.demoAccounts is a static config list [{role,name,email}], never a live users query
```

```
MODULE auth.controller
IMPORT * as authService FROM './auth.service.js'
IMPORT { success } FROM '../../common/response.util.js'
IMPORT { asyncHandler } FROM '../../common/asyncHandler.js'

CONST REFRESH_COOKIE_OPTS = { httpOnly:true, secure: env.nodeEnv=='production', sameSite:'lax',
                              path: '/api/v1/auth/refresh', maxAge: parseMs(env.refreshTtl) }

registerController = asyncHandler(async (req, res) => {
    result = await authService.register(req.validated)     // validated body set by validate() middleware
    res.cookie('accessToken', result.accessToken, {...})    // optional, for cookie-based clients
    res.cookie('refreshToken', result.refreshToken, REFRESH_COOKIE_OPTS)
    RETURN success(res, result, 201)
})

loginController = asyncHandler(async (req, res) => {
    result = await authService.login(req.validated)
    res.cookie('refreshToken', result.refreshToken, REFRESH_COOKIE_OPTS)
    RETURN success(res, result, 200)
})

refreshController = asyncHandler(async (req, res) => {
    token = req.cookies?.refreshToken OR req.body?.refreshToken
    result = await authService.refresh(token)
    res.cookie('refreshToken', result.refreshToken, REFRESH_COOKIE_OPTS)
    RETURN success(res, result, 200)
})

logoutController = asyncHandler(async (req, res) => {
    res.clearCookie('refreshToken', { path: REFRESH_COOKIE_OPTS.path })
    res.clearCookie('accessToken')
    RETURN success(res, { loggedOut: true }, 200)
})

getMeController = asyncHandler(async (req, res) => {
    result = await authService.me(req.auth.userId)
    RETURN success(res, result, 200)
})

demoAccountsController = asyncHandler(async (req, res) => {
    result = await authService.demoAccounts()
    RETURN success(res, result, 200)
})
```

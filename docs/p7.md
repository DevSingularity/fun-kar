# DealFlow360 — Phase 7 API Design
## Customer Portal + Negotiation (`plan.md` Hour 6.25–7)

Builds on Phase 1 (auth/RBAC/response envelope, `authenticate`/`authorize`), Phase 2 (admin-CRUD conventions, `pagination.util`), Phase 3 (quotation pricing engine, `evaluateQuoteRisk`/submit-for-approval routing), Phase 4 (approval decision flow), Phase 5 (`orders`/owner-rep access-check pattern, `FOR UPDATE` lock style), and Phase 6 (`invoices`/`billing_schedules`, `withTransaction`, `insertAuditLog`, `numbering.util`). Scope is strictly §7.1–7.4 of `plan.md`: a separate restricted customer-facing view, line-level negotiation, automatic re-approval when negotiated terms exceed limits, and customer confirmation. Deal Health/Reporting (Phase 8) is **not** built here.

---

## 1. Assumptions carried into this phase

1. **Two portal entry mechanisms exist in the schema and both are used, for different purposes.** `customer_users` + `portal_tokens` (magic link) or a password is the identity a negotiation/comment/confirmation action is attributed to (`negotiation_requests.customerUserId` and `negotiation_comments.authorCustomerUserId` are real FKs into `customer_users` — there is no anonymous path around that). `quotation_portal_tokens` is a **share link scoped to one quotation only**, with no `customerUserId` column at all, so it can only ever grant **read-only guest access** to that one quote — it cannot itself author a negotiation request. This resolves cleanly: reads accept either a portal session **or** a valid share token; every write (`negotiate`, `comment`, `confirm`) requires a portal session.
2. **No self-service customer signup.** The PS's "Customer... Views quotation online" role never mentions customer self-registration, and `customer_users` is a contact record under an existing `customers` row created internally (Phase 2 customer management). This phase gap-fills **`POST /customers/:customerId/portal-users`** (an owner-rep/admin action, analogous to how Phase 6 gap-filled `subscription_plans` CRUD) so a portal identity actually exists to log in as. Provisioning always creates a passwordless contact (`passwordHash = null`); the contact authenticates via magic link only, unless it later sets a password through its own account (out of scope this phase, flagged as a "build next" item).
3. **"Send to customer" is also a gap-fill this phase.** No earlier phase mints a `quotation_portal_tokens` row. `POST /quotations/:id/portal/share` is added, restricted to `quotationStatusEnum` values `APPROVED` or `NONE`-required-`DRAFT`-already-submitted (in practice: any state where `requiredApprovalLevel` resolution is not currently `PENDING`) → sets `quotations.status = 'SENT'`. Only one active share token per quotation at a time — creating a new one revokes the previous unexpired one (simpler security story than juggling multiple live links).
4. **A quotation is "portal-visible" once it has ever been shared, not only while `status = 'SENT'`.** Visibility is derived from the existence of at least one `quotation_portal_tokens` row for that quotation (regardless of expiry/revocation — the historical fact of having been sent is what matters), not from current status alone. This matters because a mid-negotiation re-approval temporarily moves `status` back to `PENDING_APPROVAL`; the customer should still be able to open the quote (read-only, "Under internal review") rather than get a 404.
5. **Orders/fulfillment/billing already exist by the time a quote reaches the portal**, per Phase 5/6's own stated assumptions (order created on approval; billing generated against that order). This phase does **not** touch `orders`/`order_items`/`fulfillment_allocations`/`billing_schedules` rows directly — a negotiated discount change only ever mutates the **quotation** (and, on customer confirmation, sets `orders.confirmedAt` and issues the pending invoice). Reconciling an already-fulfilled/invoiced order against a renegotiated price is a real gap in an 8-hour MVP and is called out explicitly in the final "what we'd build next" note rather than faked.
6. **The governance/approval engine from Phase 2–4 is reused, not reimplemented**, with one small, explicitly-flagged extension: `governance.evaluateQuoteRisk(tx, quotationId)` is unchanged, but the routing helper (originally `governance.routeForApproval(tx, quotationId, riskResult)`, defaulting the quotation's post-approval status to `'APPROVED'`) gains an optional `returnStatusIfClear` param so this phase can pass `'SENT'` — a renegotiated quote that turns out to still be within limits should return the customer to the portal, not to the pre-send `APPROVED` state.
7. **Only `COUNTER_DISCOUNT` requests can change commercial terms**, and only against exactly one named `quotationItemId` (matches the PS's own worked example — "Laptop discount, current 10%, requested 15%"). `COMMENT`/`CHANGE_REQUEST` types never touch pricing; resolving them just closes the request with a note. This keeps the schema's `requestedDiscountPct` (nullable) meaningful without inventing a requested-quantity column the schema doesn't have.
8. **Resolution of a negotiation request is an internal action** (Sales Rep or above) — matching the PS User Roles section verbatim: *"Sales Rep... Responds to customer negotiation requests."* The customer proposes; the rep (or manager/finance/ops) accepts, rejects, or returns for revision. Accepting a `COUNTER_DISCOUNT` re-runs the risk engine; the rep is never trusted to bypass governance, because acceptance only stages the new discount and re-evaluation is what actually decides whether the quote can stay `SENT` or must re-enter approval.
9. **A rejected re-approval during negotiation is not a terminal deal-kill.** If Manager/Finance rejects the quotation while it is mid-renegotiation (i.e., it was already `SENT`/`UNDER_NEGOTIATION` before this approval cycle started), the affected line's discount is reverted to its pre-negotiation value and `status` returns to `SENT` — the deal stays alive for the customer to keep negotiating or simply confirm the original terms. (A rejection on the *original*, pre-send submission still lands on the existing terminal `REJECTED` status — that behavior, built in Phase 3/4, is untouched.)
10. **Pricing/margin recalculation reuses Phase 3's pure calculators** (`quotationPricing.recalculateItem({unitPrice, quantity, discountPct, taxRate}) -> {discountAmount, taxAmount, lineTotal}` and `quotationPricing.recalculateTotals(items) -> {subtotal, discountTotal, taxTotal, grandTotal, estimatedMarginPct}`), the same functions the quotation builder already calls on every line edit — never re-derived here.
11. **The customer-facing view is a hard field allow-list**, enforced in the repository layer (not just hidden in the frontend) per `plan.md` §7.1: no `blendedRiskScore`, `estimatedMarginPct`, `estimatedCost`, `allowedDiscountPct`, internal audit entries, or other customers'/quotations' data ever serializes into a portal response.
12. **`audit_logs.actorId` is a hard FK into `users` only** — it cannot reference a `customer_users` row. Any audit entry caused by a customer action is written with `actorId = null` and the acting `customerUserId` recorded inside `newValue`/`reason` instead, so the audit trail still names who did it without violating the schema's foreign key.
13. **Payment recording (`POST /invoices/:id/payments`)** is built here per Phase 6's assumption 9 and the PS Quick Test Flow's literal ordering ("confirm the order, record a payment, check invoice status"). No real payment gateway is integrated (explicitly a post-MVP idea) — a recorded payment is treated as immediately `SUCCEEDED`; overpayment beyond `invoice.total - invoice.amountPaid` is rejected rather than silently accepted.
14. **Portal sessions are JWTs with a distinct `type: 'customer_portal'` claim**, verified by a dedicated `authenticatePortal` middleware that explicitly rejects a token missing/mismatching that claim (and vice versa for internal `authenticate`) — an internal staff JWT must never be usable against `/portal/*`, and a portal JWT must never be usable against internal routes.
15. **Magic-link requests never reveal whether an email exists.** The response is always the same generic `200`; the raw token is only ever returned inline (`devMagicLink`) when `NODE_ENV !== 'production'`, purely to keep the demo fast per `plan.md`'s "demo account selector" spirit — never in a production build.

## 3. Shared conventions

Unchanged from Phases 1–6 (`response.util.js`, `errors.js`, `asyncHandler.js`, `pagination.util.js`, `authenticate`/`authorize`, `validate(validatorFn)`, `withTransaction`, `insertAuditLog`, `generateInvoiceNumber`-style `numbering.util`). New shared pieces this phase:

- **`portalToken.util.js`** — `generateRawToken() -> 32-byte hex string`, `hashToken(raw) -> sha256 hex`. The raw value is only ever returned once, in the API response that creates it (magic-link email, share-link creation); only the hash is persisted (matches how `portal_tokens`/`quotation_portal_tokens` are already modeled).
- **`authenticatePortal` middleware** — reads `Authorization: Bearer <jwt>`, verifies `type: 'customer_portal'`, sets `req.portalAuth = { customerUserId, customerId }`. A second, lighter helper `attachShareTokenIfPresent` reads an optional `X-Quote-Token` header, hashes it, and (only for the single quotation named in the route param) resolves it to `{ customerId, tokenOnly: true }` if valid/unexpired/unrevoked — used only on the two read routes that accept either auth mode.
- **Owner-rep access check** for internal routes in this phase reuses Phase 5's pattern verbatim (`quotationWithAccessCheck(tx, quotationId, auth)` — join to `quotations.salesRepId`).

### 4.1–4.2 Portal-user provisioning
`POST` validates `name`, `email` (unique per `customer_users_email_lower_unique`), inserts with `passwordHash=null`; **does not** auto-send a magic link (kept as an explicit, separate step so a rep can provision several contacts before sharing anything). `GET` is a plain paginated list.

### 4.3 `POST /quotations/:id/portal/share`
- **Precondition:** `quotations.requiredApprovalLevel` resolution is not currently pending (i.e., no `PENDING` row in `approval_requests` for this quotation) — `409 APPROVAL_PENDING` otherwise.
- **Transaction:** lock quotation → revoke any existing unrevoked `quotation_portal_tokens` row for it (`revokedAt = now()`) → insert a new one (`expiresAt = now() + 14 days`, configurable) → set `status='SENT'` (only if not already further along — `SENT`/`UNDER_NEGOTIATION`/`CONFIRMED` all pass through unchanged, since re-sharing a link shouldn't regress a confirmed deal) → `lastActivityAt=now()` → audit log.
- **Success:** `200 { shareUrl, rawToken, expiresAt }` — `rawToken` shown once.

### 4.4–4.7 Portal auth
Magic-link request always `200` regardless of email match (assumption 15). Consume: hash token → row must exist, `usedAt IS NULL`, `expiresAt > now()` (else `410 TOKEN_EXPIRED`/`404`) → mark `usedAt` → issue session JWT. Login: constant-time password compare via bcrypt, generic `401 INVALID_CREDENTIALS` on any mismatch (no user-enumeration). `me`: returns `{ customerUserId, name, email, customer: { id, name, tier } }`.

### 4.8 `GET /portal/quotes`
Session required. Paginated list of quotations where `customerId = portalAuth.customerId` **and** at least one `quotation_portal_tokens` row exists for it (assumption 4) — one indexed `EXISTS` subquery, no N+1.

### 4.9 `GET /portal/quotes/:id`
Accepts session or share token (must match `:id` exactly — a share token never grants access to any other quotation). Returns the allow-listed shape: quote number, status, customer name, line items (`product name, quantity, unitPrice, discountPct, taxAmount, lineTotal` — **no** `allowedDiscountPct`/`estimatedCost`/`isUpsell`), `subtotal/discountTotal/taxTotal/grandTotal`, `promisedDeliveryDate`. Internal-only fields are never selected, not merely stripped after the fact.

### 4.10 `POST /portal/quotes/:id/negotiation-requests`
Session required (customerUserId comes from the session, never the body). **Precondition:** quotation currently `status IN ('SENT','UNDER_NEGOTIATION')` (else `409 NOT_NEGOTIABLE`). For `COUNTER_DISCOUNT`: `quotationItemId` required and must belong to this quotation; `requestedDiscountPct` required, `0–100`. Inserts `negotiation_requests` (`OPEN`) + a mirrored `negotiation_comments` row (`authorType='CUSTOMER'`) → bumps `status` to `UNDER_NEGOTIATION` if it was `SENT` → `lastActivityAt=now()`.

### 4.11 `POST /portal/quotes/:id/comments`
Session required. Free-standing `negotiation_comments` row, optionally threaded under an existing `negotiationRequestId` owned by the same quotation.

### 4.12 `GET .../negotiation` (both internal and portal variants)
One query each on `negotiation_requests` and `negotiation_comments` for the quotation, merged and sorted by `createdAt`; portal variant additionally filters out nothing (both sides see the same thread — the PS explicitly wants a shared timeline) but still comes from the allow-listed repository (no internal risk/audit rows mixed in).

### 4.13 `POST /negotiation-requests/:id/resolve`
- **Body:** `{ decision: 'ACCEPT'|'REJECT'|'RETURN', resolutionNote }`.
- **Idempotency:** already-resolved request → `409 ALREADY_RESOLVED` (resolution is a one-time state transition, not repeatable).
- **Transaction:** lock the request row (must be `OPEN`) → lock parent quotation → branch:
  - **`REJECT`/`RETURN`:** just close the request (`status` accordingly), insert a system comment, audit log. No pricing change.
  - **`ACCEPT`, type `COMMENT`/`CHANGE_REQUEST`:** same as above — closing with a note is the entire effect (assumption 7).
  - **`ACCEPT`, type `COUNTER_DISCOUNT`:** lock the target `quotation_items` row → snapshot old `discountPct` → apply `requestedDiscountPct` → `quotationPricing.recalculateItem(...)` → update the item → `quotationPricing.recalculateTotals(all items)` → update quotation totals → `governance.evaluateQuoteRisk(tx, quotationId)` → IF clear: `governance.routeForApproval(tx, quotationId, riskResult, { returnStatusIfClear: 'SENT' })` (this either leaves it `SENT` or, if still risky, opens a new `approval_requests` row and sets `status='PENDING_APPROVAL'`) → close the negotiation request `RESOLVED` → audit log with full before/after discount + risk snapshot.
- **Success:** `200 { negotiationRequest, quotationItem?, quotation, riskResult? }`.

### 4.14 `POST /invoices/:id/payments`
- **Body:** `{ amount, method, transactionReference? }`.
- **Transaction:** lock invoice → must be `status IN ('ISSUED','PARTIALLY_PAID')` (else `409 INVALID_STATE`) → `amount > 0` and `amount <= total - amountPaid` (else `422 OVERPAYMENT`) → insert `payments` row (`status='SUCCEEDED'`, `paidAt=now()` — assumption 13, no gateway) → `invoice.amountPaid += amount` → `invoice.status = (amountPaid==total) ? 'PAID' : 'PARTIALLY_PAID'` → audit log.
- **Success:** `201 { payment, invoice }`.

**File: `server/src/middlewares/authenticatePortal.middleware.js`**
```
MODULE authenticatePortal.middleware
IMPORT { verifyJwt } FROM '../common/jwt.util.js'
IMPORT { UnauthorizedError } FROM '../common/errors.js'

FUNCTION authenticatePortal(req, res, next):
    token = extractBearer(req.headers.authorization)
    IF NOT token: THROW UnauthorizedError('Portal session required.')
    payload = TRY verifyJwt(token) CATCH: THROW UnauthorizedError('Invalid or expired session.')
    IF payload.type != 'customer_portal': THROW UnauthorizedError('Invalid session type.')
    req.portalAuth = { customerUserId: payload.sub, customerId: payload.customerId }
    next()

// Used only on the two read routes that also accept a bare share token.
FUNCTION attachShareTokenIfPresent(req, res, next):
    raw = req.headers['x-quote-token']
    IF NOT raw: RETURN next()
    tokenHash = hashToken(raw)
    row = db.select().from(quotationPortalTokens)
           .where(and(eq(quotationPortalTokens.quotationId, req.params.id),
                      eq(quotationPortalTokens.tokenHash, tokenHash),
                      isNull(quotationPortalTokens.revokedAt),
                      gt(quotationPortalTokens.expiresAt, now()))).first()
    IF row:
        quote = db.select({ customerId: quotations.customerId }).from(quotations)
                  .where(eq(quotations.id, req.params.id)).first()
        req.shareTokenAuth = { customerId: quote.customerId, tokenOnly: true }
    next()

EXPORT { authenticatePortal, attachShareTokenIfPresent }
```

```
MODULE portalAuth.validator

FUNCTION validateMagicLinkRequest(body):
    errors = []
    IF NOT isEmail(body.email): errors.push('A valid email is required.')
    RETURN { valid: errors.empty, errors, clean: { email: trim(body.email).toLowerCase() } }

FUNCTION validateMagicLinkConsume(body):
    errors = []
    IF NOT trim(body.token): errors.push('token is required.')
    RETURN { valid: errors.empty, errors, clean: { token: trim(body.token) } }

FUNCTION validateLogin(body):
    errors = []
    IF NOT isEmail(body.email): errors.push('A valid email is required.')
    IF NOT body.password: errors.push('password is required.')
    RETURN { valid: errors.empty, errors, clean: { email: trim(body.email).toLowerCase(), password: body.password } }
```

```
    db.select().from(portalTokens)
      .where(and(eq(portalTokens.tokenHash, tokenHash), isNull(portalTokens.usedAt), gt(portalTokens.expiresAt, now())))
```

**File: `server/src/modules/portalAuth/portalAuth.service.js`**
```
MODULE portalAuth.service
IMPORT * as repo FROM './portalAuth.repository.js'
IMPORT { generateRawToken, hashToken } FROM '../../common/portalToken.util.js'
IMPORT { signJwt } FROM '../../common/jwt.util.js'
IMPORT { UnauthorizedError } FROM '../../common/errors.js'
IMPORT bcrypt FROM 'bcrypt'

CONST MAGIC_LINK_TTL_MINUTES = 30

FUNCTION requestMagicLink(email):
    user = await repo.findActiveByEmail(email)
    IF NOT user: RETURN { sent: true }   // never reveal existence (assumption 15)
    raw = generateRawToken()
    await repo.insertToken({ customerUserId: user.id, tokenHash: hashToken(raw),
                             expiresAt: addMinutes(now(), MAGIC_LINK_TTL_MINUTES) })
    result = { sent: true }
    IF env.NODE_ENV != 'production': result.devMagicLink = raw   // assumption 15, demo convenience only
    RETURN result

FUNCTION issueSession(customerUser):
    token = signJwt({ sub: customerUser.id, customerId: customerUser.customerId, type: 'customer_portal' },
                     { expiresIn: '2h' })
    RETURN { token, customerUser: { id: customerUser.id, name: customerUser.name, email: customerUser.email,
                                     customerId: customerUser.customerId } }

FUNCTION consumeMagicLink(rawToken):
    row = await repo.findValidToken(hashToken(rawToken))
    IF NOT row: THROW UnauthorizedError('Link is invalid or has expired.')
    await repo.markTokenUsed(row.id)
    user = await repo.findById(row.customerUserId)
    RETURN issueSession(user)

FUNCTION login({ email, password }):
    user = await repo.findActiveByEmail(email)
    IF NOT user OR NOT user.passwordHash: THROW UnauthorizedError('Invalid email or password.')
    match = await bcrypt.compare(password, user.passwordHash)
    IF NOT match: THROW UnauthorizedError('Invalid email or password.')
    RETURN issueSession(user)

FUNCTION me(customerUserId):
    user = await repo.findById(customerUserId)
    IF NOT user: THROW UnauthorizedError('Session no longer valid.')
    RETURN { id: user.id, name: user.name, email: user.email, customerId: user.customerId }
```

```
CONST REQUEST_TYPES = ['COMMENT','CHANGE_REQUEST','COUNTER_DISCOUNT']
CONST DECISIONS = ['ACCEPT','REJECT','RETURN']

FUNCTION validateCreateRequest(body):
    errors = []
    IF NOT REQUEST_TYPES.includes(body.requestType): errors.push('requestType must be one of ' + REQUEST_TYPES.join(','))
    IF NOT trim(body.message): errors.push('message is required.')
    clean = { requestType: body.requestType, message: trim(body.message), quotationItemId: undefined, requestedDiscountPct: undefined }
    IF body.requestType == 'COUNTER_DISCOUNT':
        IF NOT isUuid(body.quotationItemId): errors.push('quotationItemId is required for a counter-discount.')
        pct = numeric(body.requestedDiscountPct)
        IF NOT isFinite(pct) OR pct < 0 OR pct > 100: errors.push('requestedDiscountPct must be between 0 and 100.')
        clean.quotationItemId = body.quotationItemId
        clean.requestedDiscountPct = pct
    ELSE IF body.quotationItemId != undefined:
        IF NOT isUuid(body.quotationItemId): errors.push('quotationItemId must be a valid UUID.')
        clean.quotationItemId = body.quotationItemId
    RETURN { valid: errors.empty, errors, clean }

FUNCTION validateComment(body):
    errors = []
    IF NOT trim(body.message): errors.push('message is required.')
    IF body.negotiationRequestId != undefined AND NOT isUuid(body.negotiationRequestId):
        errors.push('negotiationRequestId must be a valid UUID.')
    RETURN { valid: errors.empty, errors,
        clean: { message: trim(body.message), negotiationRequestId: body.negotiationRequestId } }

FUNCTION validateResolve(body):
    errors = []
    IF NOT DECISIONS.includes(body.decision): errors.push('decision must be one of ' + DECISIONS.join(','))
    IF NOT trim(body.resolutionNote): errors.push('resolutionNote is required.')
    RETURN { valid: errors.empty, errors, clean: { decision: body.decision, resolutionNote: trim(body.resolutionNote) } }
```

```
// ---- 4.13 internal: resolve ----
FUNCTION resolveRequest(requestId, { decision, resolutionNote }, auth):
    RETURN await withTransaction(async (tx) => {
        request = await repo.lockRequest(tx, requestId)
        IF NOT request: THROW NotFoundError('Negotiation request')
        IF request.status != 'OPEN': THROW ConflictError('ALREADY_RESOLVED', 'This request has already been resolved.')
        quote = await quotationWithAccessCheck(tx, request.quotationId, auth)   // FOR UPDATE inside

        result = { negotiationRequest: null, quotationItem: undefined, quotation: quote, riskResult: undefined }

        IF decision != 'ACCEPT' OR request.requestType != 'COUNTER_DISCOUNT':
            resolvedStatus = (decision == 'ACCEPT') ? 'RESOLVED' : 'REJECTED'
            result.negotiationRequest = await repo.updateRequest(tx, requestId,
                { status: resolvedStatus, resolvedBy: auth.userId, resolutionNote, resolvedAt: now() })
        ELSE:
            item = await repo.findItemInQuotation(tx, request.quotationItemId, quote.id)
            IF NOT item: THROW NotFoundError('Quotation item')
            oldDiscountPct = item.discountPct

            recalculated = pricing.recalculateItem({ unitPrice:item.unitPrice, quantity:item.quantity,
                discountPct: request.requestedDiscountPct, taxRate: item.product.taxRate })
            tx.update(quotationItems).set({ discountPct: request.requestedDiscountPct, ...recalculated })
              .where(eq(quotationItems.id, item.id))

            allItems = tx.select().from(quotationItems).where(eq(quotationItems.quotationId, quote.id))
            totals = pricing.recalculateTotals(allItems)
            tx.update(quotations).set({ ...totals, lastActivityAt: now() }).where(eq(quotations.id, quote.id))

            riskResult = await governance.evaluateQuoteRisk(tx, quote.id)
            routed = await governance.routeForApproval(tx, quote.id, riskResult, { returnStatusIfClear: 'SENT' })

            result.negotiationRequest = await repo.updateRequest(tx, requestId,
                { status:'RESOLVED', resolvedBy: auth.userId, resolutionNote, resolvedAt: now() })
            result.quotationItem = { id: item.id, discountPct: request.requestedDiscountPct, ...recalculated }
            result.quotation = routed.quotation
            result.riskResult = riskResult

            await insertAuditLog(tx, { actorId: auth.userId, entityType:'QUOTATION_ITEM', entityId: item.id,
                action:'DISCOUNT_RENEGOTIATED', reason: resolutionNote,
                oldValue: { discountPct: oldDiscountPct }, newValue: { discountPct: request.requestedDiscountPct,
                blendedRiskScore: riskResult.blendedRiskScore, requiredApprovalLevel: routed.requiredApprovalLevel } })

        await repo.insertComment(tx, { negotiationRequestId: requestId, quotationId: quote.id,
            authorType:'INTERNAL', authorUserId: auth.userId, message: resolutionNote })

        RETURN result
    })
```

```
MODULE payments.validator

FUNCTION validateCreate(body):
    errors = []
    amount = numeric(body.amount)
    IF NOT isFinite(amount) OR amount <= 0: errors.push('amount must be a positive number.')
    IF NOT trim(body.method): errors.push('method is required.')
    RETURN { valid: errors.empty, errors,
        clean: { amount: amount?.toFixed(2), method: trim(body.method), transactionReference: trim(body.transactionReference) OR null } }
```

```
MODULE payments.repository
IMPORT { invoices, payments, orders, quotations } FROM '../../db/schema/index.js'

FUNCTION invoiceWithAccessCheck(tx, invoiceId, auth):
    row = tx.select({ invoice: invoices, salesRepId: quotations.salesRepId })
            .from(invoices).innerJoin(orders, eq(invoices.orderId, orders.id))
            .innerJoin(quotations, eq(orders.quotationId, quotations.id))
            .where(eq(invoices.id, invoiceId)).for('update').first()
    IF NOT row: THROW NotFoundError('Invoice')
    IF auth.role == 'SALES_REP' AND row.salesRepId != auth.userId: THROW ForbiddenError()
    RETURN row.invoice

FUNCTION insertPayment(tx, data) -> tx.insert(payments).values(data).returning().first()
FUNCTION updateInvoice(tx, id, data) -> tx.update(invoices).set(data).where(eq(invoices.id, id)).returning().first()

FUNCTION list(invoiceId, { offset, limit }, auth):
    invoiceWithAccessCheck(db, invoiceId, auth)   // read-only guard, no lock needed
    rows = db.select().from(payments).where(eq(payments.invoiceId, invoiceId)).orderBy(desc(payments.createdAt)).limit(limit).offset(offset)
    total = db.select({ count: sql`count(*)` }).from(payments).where(eq(payments.invoiceId, invoiceId)).first()
    RETURN { rows, total }
```

```
MODULE payments.service
IMPORT * as repo FROM './payments.repository.js'
IMPORT { withTransaction } FROM '../../db/index.js'
IMPORT { ConflictError, ValidationError } FROM '../../common/errors.js'
IMPORT { insertAuditLog } FROM '../../common/repoHelpers.js'
IMPORT { parseListQuery, buildMeta } FROM '../../common/pagination.util.js'

FUNCTION recordPayment(invoiceId, { amount, method, transactionReference }, auth):
    RETURN await withTransaction(async (tx) => {
        invoice = await repo.invoiceWithAccessCheck(tx, invoiceId, auth)
        IF NOT ['ISSUED','PARTIALLY_PAID'].includes(invoice.status):
            THROW ConflictError('INVALID_STATE', 'Invoice must be issued before recording a payment.')
        remaining = invoice.total - invoice.amountPaid
        IF Number(amount) > Number(remaining): THROW ValidationError([`Amount exceeds remaining balance of ${remaining}.`])

        payment = await repo.insertPayment(tx, { invoiceId, amount, method, transactionReference,
            status:'SUCCEEDED', paidAt: now() })
        newAmountPaid = round(Number(invoice.amountPaid) + Number(amount), 2)
        updatedInvoice = await repo.updateInvoice(tx, invoiceId,
            { amountPaid: newAmountPaid, status: (newAmountPaid == Number(invoice.total)) ? 'PAID' : 'PARTIALLY_PAID' })

        await insertAuditLog(tx, { actorId: auth.userId, entityType:'INVOICE', entityId: invoiceId,
            action:'PAYMENT_RECORDED', newValue: { paymentId: payment.id, amount, newStatus: updatedInvoice.status } })

        RETURN { payment, invoice: updatedInvoice }
    })

FUNCTION list(invoiceId, query, auth):
    { page, pageSize, offset } = parseListQuery(query, { allowedSortColumns:['createdAt'], defaultSort:'createdAt' })
    { rows, total } = await repo.list(invoiceId, { offset, limit: pageSize }, auth)
    RETURN { items: rows, meta: buildMeta({ page, pageSize, total }) }
```

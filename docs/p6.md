## 1. Assumptions carried into this phase

1. **`subscription_plans` admin config (`plan.md` §A5) is a gap filled here**, not in Phase 2 — Phase 2 scoped itself to §2.1–2.5 only, and this phase is the first real consumer of that table.
2. **No schema column anywhere links a `SUBSCRIPTION` product to a `subscription_plans` row** — not on `products`, `quotation_items`, or `order_items`. The actual attachment point the schema provides is `subscription_lines` itself (`orderItemId` unique + `subscriptionPlanId`). So `POST /orders/:id/billing/generate` (this phase's gap-fill, analogous to Phase 5's order-creation endpoint) takes an explicit `subscriptionAssignments` array mapping each `RECURRING` order item to its plan, rather than inferring it — this keeps every earlier phase's schema and flow untouched.
3. **Recurring amount = `orderItem.lineTotal`, never `subscriptionPlans.price × quantity`.** Re-pricing from the plan's list price would bypass the discount governance/approval already applied to that line in Phases 3–4. The plan's `price` is a reference/list price only.
4. **One-time invoice tax is computed per line from `products.taxRate` at generation time**, since `order_items` has no per-line tax column (only `orders.taxTotal` is an aggregate).
5. **Billing generation is an explicit call, not triggered by order confirmation or a cron job** — consistent with the Quick Test Flow's ordering (billing is checked before the portal step) and Rule 5 (no unnecessary infrastructure).
6. **Only the current cycle is ever materialized as a `billing_schedules` row.** `subscriptionLines.nextBillingDate` (not a second schedule row) drives the "Next billing: Oct 5" display. Auto-rolling future cycles is a scheduler concern explicitly out of scope this phase (P2/bonus in `plan.md`'s priority matrix) — flagged as a "build next" item, not faked.
7. **Proration on `/subscriptions/:id/change` blends the elapsed days at the old rate with the remaining days at the new rate**, applying `plan.md` §6.3's formula twice and summing — genuinely calculated, not faked, and satisfies "support at least one mid-cycle change" without inventing a table the schema doesn't have.
8. **Credit notes are only created for cycles already invoiced/paid.** If the current cycle is still `SCHEDULED` (nothing collected yet), the schedule amount is simply reduced — nothing to refund.
9. **Recording a payment (`payments` table) is deferred to Phase 7.** The PS Quick Test Flow lists "record a payment" *after* customer confirmation, and `plan.md`'s own Phase 6 / Billing API list never mentions a payment-recording endpoint. Built alongside Phase 7's confirmation wiring.
10. **Roles:** `subscription_plans` config is `ADMIN`-only. Billing **generation/reads** follow Phase 5's convention — owner `SALES_REP` + `SALES_MANAGER`/`FINANCE`/`OPERATIONS`/`ADMIN`. **Mutating a live commitment** (`change`/`cancel`) is restricted to `SALES_MANAGER`/`FINANCE`/`OPERATIONS`/`ADMIN` only, matching the PS's "Finance/Operations ... reconciles recurring billing and credit notes."
11. **Billing mutations never write to `orders`/`order_items`/`quotations`** — same read-only-input boundary Phase 5 established.

### 4.1–4.2 Subscription plan CRUD
Standard admin CRUD, mirroring Phase 2: `name` unique, `frequency ∈ {MONTHLY,QUARTERLY,YEARLY}`, `price ≥ 0`, `prorationEnabled` (default true), `cancellationNoticeDays ≥ 0`. `PATCH .../isActive=false` is the only "delete" (hard delete blocked by `subscription_lines.subscriptionPlanId` `onDelete:'restrict'`).

### 4.3 `POST /orders/:id/billing/generate`
- **Body:** `{ subscriptionAssignments: [{ orderItemId, subscriptionPlanId }] }` — required only for `RECURRING` items lacking a `subscription_lines` row yet.
- **Idempotency:** one-time side keyed on existing `invoices(orderId, invoiceType='ONE_TIME')`; recurring side keyed on `subscription_lines_order_item_id_unique` — an already-attached item is skipped, even if resent.
- **Transaction:** lock order → load items+products → build missing invoice (bulk `invoiceLines` insert) → for each unattached recurring item, insert `subscription_lines` + its first `billing_schedules` row → one audit log. A line whose assignment is missing/invalid is reported in `recurringPending`, not thrown — it never blocks the rest of the call.
- **Success:** `200 { invoice, subscriptionLines, recurringPending? }` (always `200`, since this is upsert-shaped).
- **Errors:** `403`, `404`, `400` (malformed body shape only).

### 4.4 `GET /orders/:id/billing`
Three flat, indexed queries (invoice+lines, recurring lines joined to plan/product, credit notes) — no N+1. Returns `{ oneTime, recurring[], creditNotes[] }`; `oneTime` is `null` until generated.

### 4.5 `GET /orders/:id/schedule`
One paginated, joined query scoped via an `IN`-subquery on the order's item ids; sorted by `billingPeriodStart`.

### 4.6 `POST /subscriptions/:id/change`
- **Body:** `{ newQuantity?, newSubscriptionPlanId?, reason }` — at least one of the first two required.
- **Flow:** lock subscription line (`status` must be `ACTIVE`) → lock the cycle covering today (`409 NO_ACTIVE_CYCLE` if none) → compute `cycleDays`/`usedDays`/`remainingDays` → blend `oldAmount×usedDays/cycleDays + newFullCycleAmount×remainingDays/cycleDays` (skip blending if `plan.prorationEnabled=false`) → update the schedule (`isProrated=true`) and the line's `recurringAmount` (for future cycles) → audit log with full before/after breakdown.
- **Success:** `200 { subscriptionLine, currentCycle, proration:{ usedDays, remainingDays, cycleDays, oldAmount, newFullCycleAmount } }` — the explicit breakdown powers `plan.md`'s "show the calculation" bonus.

### 4.7 `POST /subscriptions/:id/cancel`
- **Body:** `{ reason }`.
- **Idempotency:** already-`CANCELLED` → `200` + existing credit note, `meta:{alreadyCancelled:true}`.
- **Flow:** lock line → lock current cycle (if any) → `unusedAmount = prorate(schedule.amount, remainingDays, cycleDays)` when `prorationEnabled` → if cycle `SCHEDULED`, just shrink its amount (nothing to refund); if `INVOICED`/`PAID`, issue a `credit_notes` row → mark line `CANCELLED` → audit log.
- **Success:** `200 { subscriptionLine, creditNote, unusedAmount }`.

```
MODULE subscriptionPlans.validator
CONST FREQUENCIES = ['MONTHLY','QUARTERLY','YEARLY']

FUNCTION validateCreate(body):
    errors = []
    name = trim(body.name)
    IF name.length NOT IN [1,100]: errors.push('Name is required (max 100 chars).')
    IF NOT FREQUENCIES.includes(body.frequency): errors.push('frequency must be one of ' + FREQUENCIES.join(','))
    price = numeric(body.price)
    IF NOT isFinite(price) OR price < 0: errors.push('price must be a non-negative number.')
    cancellationNoticeDays = int(body.cancellationNoticeDays) OR 0
    IF cancellationNoticeDays < 0: errors.push('cancellationNoticeDays cannot be negative.')
    clean = { name, frequency: body.frequency, price: price.toFixed(2),
              prorationEnabled: body.prorationEnabled != false, cancellationNoticeDays }
    RETURN { valid: errors.empty, errors, clean }

FUNCTION validateUpdate(body):
    errors = []
    clean = {}
    IF body.name != undefined:
        IF NOT trim(body.name): errors.push('Name cannot be empty.')
        ELSE clean.name = trim(body.name)
    IF body.frequency != undefined:
        IF NOT FREQUENCIES.includes(body.frequency): errors.push('Invalid frequency.')
        ELSE clean.frequency = body.frequency
    IF body.price != undefined:
        p = numeric(body.price)
        IF NOT isFinite(p) OR p < 0: errors.push('price must be a non-negative number.')
        ELSE clean.price = p.toFixed(2)
    IF body.prorationEnabled != undefined: clean.prorationEnabled = !!body.prorationEnabled
    IF body.cancellationNoticeDays != undefined:
        d = int(body.cancellationNoticeDays)
        IF d < 0: errors.push('cancellationNoticeDays cannot be negative.')
        ELSE clean.cancellationNoticeDays = d
    IF body.isActive != undefined: clean.isActive = !!body.isActive
    RETURN { valid: errors.empty, errors, clean }
```

```
MODULE billing.proration

FUNCTION cycleEnd(startDate, frequency):
    SWITCH frequency:
        CASE 'MONTHLY':   RETURN addMonths(startDate, 1).minusDays(1)
        CASE 'QUARTERLY': RETURN addMonths(startDate, 3).minusDays(1)
        CASE 'YEARLY':    RETURN addYears(startDate, 1).minusDays(1)

FUNCTION daysBetweenInclusive(start, end) -> diffInDays(end, start) + 1
FUNCTION daysBetween(start, today)        -> MAX(0, diffInDays(today, start))

// plan.md §6.3: prorated amount = full-cycle price × active days / cycle days
FUNCTION prorate(amount, activeDays, cycleDays) -> round((amount * activeDays) / cycleDays, 2)

FUNCTION blendChange({ oldAmount, newFullCycleAmount, cycleDays, usedDays }):
    remainingDays = cycleDays - usedDays
    RETURN round(prorate(oldAmount, usedDays, cycleDays) + prorate(newFullCycleAmount, remainingDays, cycleDays), 2)
```

```
MODULE billing.service
IMPORT * as repo FROM './billing.repository.js'
IMPORT * as proration FROM './billing.proration.js'
IMPORT { withTransaction } FROM '../../db/index.js'
IMPORT { NotFoundError, ForbiddenError, ConflictError, ValidationError } FROM '../../common/errors.js'
IMPORT { parseListQuery, buildMeta } FROM '../../common/pagination.util.js'
IMPORT { generateInvoiceNumber } FROM '../../common/numbering.util.js'

CONST INVOICE_NET_DAYS = env.INVOICE_NET_DAYS OR 15

// ---- 4.3 POST /orders/:id/billing/generate ----
FUNCTION generateBilling(orderId, subscriptionAssignments, auth):
    RETURN await withTransaction(async (tx) => {
        order = await repo.orderWithAccessCheck(tx, orderId, auth)
        items = await repo.itemsWithProduct(tx, orderId)
        oneTimeItems  = items.filter(i => i.orderItem.billingLineType == 'ONE_TIME')
        recurringItems = items.filter(i => i.orderItem.billingLineType == 'RECURRING')

        // ---- one-time invoice ----
        invoice = await repo.findOneTimeInvoice(tx, orderId)
        IF NOT invoice AND oneTimeItems.length:
            subtotal = sum(oneTimeItems.map(i => i.orderItem.lineTotal))
            taxTotal = round(sum(oneTimeItems.map(i => i.orderItem.lineTotal * i.product.taxRate / 100)), 2)
            invoice = await repo.insertInvoiceWithLines(tx, {
                invoiceNumber: await generateInvoiceNumber(tx), orderId, customerId: order.customerId,
                invoiceType: 'ONE_TIME', status: 'ISSUED', subtotal, taxTotal, total: subtotal + taxTotal,
                dueDate: addDays(today(), INVOICE_NET_DAYS), issuedAt: now()
            }, oneTimeItems.map(i => ({ orderItemId: i.orderItem.id, description: i.product.name, amount: i.orderItem.lineTotal })))

        // ---- recurring lines ----
        newLines = []
        missingAssignments = []
        FOR item IN recurringItems:
            existing = await repo.findSubscriptionLineByOrderItem(tx, item.orderItem.id)
            IF existing: newLines.push(existing); CONTINUE

            assignment = subscriptionAssignments.find(a => a.orderItemId == item.orderItem.id)
            IF NOT assignment: missingAssignments.push({ orderItemId: item.orderItem.id, reason: 'No subscriptionPlanId supplied.' }); CONTINUE

            plan = await repo.findPlanById(tx, assignment.subscriptionPlanId)
            IF NOT plan OR NOT plan.isActive: missingAssignments.push({ orderItemId: item.orderItem.id, reason: 'Invalid or inactive subscription plan.' }); CONTINUE

            startDate = today()
            line = await repo.insertSubscriptionLineWithSchedule(tx,
                { orderItemId: item.orderItem.id, subscriptionPlanId: plan.id, quantity: item.orderItem.quantity,
                  recurringAmount: item.orderItem.lineTotal, startDate, nextBillingDate: startDate, status: 'ACTIVE' },
                { billingPeriodStart: startDate, billingPeriodEnd: proration.cycleEnd(startDate, plan.frequency),
                  amount: item.orderItem.lineTotal, isProrated: false, status: 'SCHEDULED' })
            newLines.push(line)

        await repo.insertAuditLog(tx, { actorId: auth.userId, entityType: 'ORDER', entityId: orderId,
            action: 'BILLING_GENERATED', newValue: { invoiceId: invoice?.id, subscriptionLineIds: newLines.map(l=>l.id) } })

        RETURN { invoice, subscriptionLines: newLines, recurringPending: missingAssignments,
                 incomplete: missingAssignments.length > 0 }
    })

FUNCTION getSchedule(orderId, query, auth):
    await repo.orderWithAccessCheck(db, orderId, auth)
    { page, pageSize, offset, sortDir } = parseListQuery(query, { allowedSortColumns:['billingPeriodStart'], defaultSort:'billingPeriodStart' })
    { rows, total } = await repo.readSchedulePage(orderId, { status: query.status, offset, limit: pageSize, sortDir })
    schedules = rows.map(r => ({ id: r.billingSchedules.id, productName: r.products.name,
        billingPeriodStart: r.billingSchedules.billingPeriodStart, billingPeriodEnd: r.billingSchedules.billingPeriodEnd,
        amount: r.billingSchedules.amount, isProrated: r.billingSchedules.isProrated,
        status: r.billingSchedules.status, invoiceId: r.billingSchedules.invoiceId }))
    RETURN { schedules, meta: buildMeta({ page, pageSize, total }) }

// ---- 4.6 POST /subscriptions/:id/change ----
FUNCTION changeSubscription(subscriptionLineId, { newQuantity, newSubscriptionPlanId, reason }, auth):
    RETURN await withTransaction(async (tx) => {
        line = await repo.lockSubscriptionLine(tx, subscriptionLineId)
        IF NOT line: THROW NotFoundError('Subscription line')
        IF line.status != 'ACTIVE': THROW ConflictError('INVALID_STATE', 'Only an active subscription can be changed.')

        currentPlan = await repo.findPlanById(tx, line.subscriptionPlanId)
        schedule = await repo.currentCycleSchedule(tx, line.id, today())
        IF NOT schedule: THROW ConflictError('NO_ACTIVE_CYCLE', 'No open billing cycle to prorate.')

        newPlan = currentPlan
        IF newSubscriptionPlanId AND newSubscriptionPlanId != line.subscriptionPlanId:
            newPlan = await repo.findPlanById(tx, newSubscriptionPlanId)
            IF NOT newPlan OR NOT newPlan.isActive: THROW ValidationError(['Invalid or inactive subscription plan.'])

        newQty = newQuantity OR line.quantity
        perUnit = line.recurringAmount / line.quantity
        newFullCycleAmount = (newPlan.id != currentPlan.id) ? (newPlan.price * newQty) : (perUnit * newQty)

        cycleDays = proration.daysBetweenInclusive(schedule.billingPeriodStart, schedule.billingPeriodEnd)
        usedDays = proration.daysBetween(schedule.billingPeriodStart, today())
        blendedAmount = currentPlan.prorationEnabled
            ? proration.blendChange({ oldAmount: schedule.amount, newFullCycleAmount, cycleDays, usedDays })
            : newFullCycleAmount

        updatedSchedule = await repo.updateSchedule(tx, schedule.id, { amount: blendedAmount, isProrated: true })
        updatedLine = await repo.updateSubscriptionLine(tx, line.id,
            { quantity: newQty, subscriptionPlanId: newPlan.id, recurringAmount: newFullCycleAmount })

        await repo.insertAuditLog(tx, { actorId: auth.userId, entityType: 'SUBSCRIPTION_LINE', entityId: line.id,
            action: 'CHANGED', reason,
            oldValue: { quantity: line.quantity, subscriptionPlanId: line.subscriptionPlanId, cycleAmount: schedule.amount },
            newValue: { quantity: newQty, subscriptionPlanId: newPlan.id, cycleAmount: blendedAmount } })

        RETURN { subscriptionLine: updatedLine, currentCycle: updatedSchedule,
                 proration: { usedDays, remainingDays: cycleDays - usedDays, cycleDays, oldAmount: schedule.amount, newFullCycleAmount } }
    })

// ---- 4.7 POST /subscriptions/:id/cancel ----
FUNCTION cancelSubscription(subscriptionLineId, { reason }, auth):
    RETURN await withTransaction(async (tx) => {
        line = await repo.lockSubscriptionLine(tx, subscriptionLineId)
        IF NOT line: THROW NotFoundError('Subscription line')

        IF line.status == 'CANCELLED':
            existingCreditNote = await repo.findCreditNoteByLine(tx, line.id)
            RETURN { subscriptionLine: line, creditNote: existingCreditNote, unusedAmount: existingCreditNote?.amount OR 0,
                     alreadyCancelled: true }

        plan = await repo.findPlanById(tx, line.subscriptionPlanId)
        schedule = await repo.currentCycleSchedule(tx, line.id, today())

        unusedAmount = 0
        creditNote = null
        IF schedule AND plan.prorationEnabled:
            cycleDays = proration.daysBetweenInclusive(schedule.billingPeriodStart, schedule.billingPeriodEnd)
            usedDays = proration.daysBetween(schedule.billingPeriodStart, today())
            remainingDays = cycleDays - usedDays
            unusedAmount = proration.prorate(schedule.amount, remainingDays, cycleDays)
            usedAmount = round(schedule.amount - unusedAmount, 2)

            IF schedule.status == 'SCHEDULED':
                await repo.updateSchedule(tx, schedule.id, { amount: usedAmount, isProrated: true, status: 'SKIPPED' })
            ELSE IF ['INVOICED','PAID'].includes(schedule.status) AND unusedAmount > 0:
                creditNote = await repo.insertCreditNote(tx, { subscriptionLineId: line.id, invoiceId: schedule.invoiceId,
                    amount: unusedAmount, reason, status: 'ISSUED' })

        updatedLine = await repo.updateSubscriptionLine(tx, line.id, { status: 'CANCELLED', cancelledAt: now(), endDate: today() })

        await repo.insertAuditLog(tx, { actorId: auth.userId, entityType: 'SUBSCRIPTION_LINE', entityId: line.id,
            action: 'CANCELLED', reason, newValue: { unusedAmount, creditNoteId: creditNote?.id } })

        RETURN { subscriptionLine: updatedLine, creditNote, unusedAmount }
    })
```

```
MODULE billing.validator

FUNCTION validateGenerate(body):
    errors = []
    assignments = Array.isArray(body.subscriptionAssignments) ? body.subscriptionAssignments : []
    seen = new Set()
    clean = []
    FOR a IN assignments:
        IF NOT isUuid(a.orderItemId): errors.push('Each assignment needs a valid orderItemId.')
        IF NOT isUuid(a.subscriptionPlanId): errors.push('Each assignment needs a valid subscriptionPlanId.')
        IF seen.has(a.orderItemId): errors.push(`Duplicate assignment for orderItemId ${a.orderItemId}.`)
        seen.add(a.orderItemId)
        clean.push({ orderItemId: a.orderItemId, subscriptionPlanId: a.subscriptionPlanId })
    RETURN { valid: errors.empty, errors, clean: { subscriptionAssignments: clean } }

FUNCTION validateChange(body):
    errors = []
    IF body.newQuantity == undefined AND body.newSubscriptionPlanId == undefined:
        errors.push('At least one of newQuantity or newSubscriptionPlanId is required.')
    IF body.newQuantity != undefined:
        q = int(body.newQuantity)
        IF NOT isInteger(q) OR q <= 0: errors.push('newQuantity must be a positive integer.')
    IF body.newSubscriptionPlanId != undefined AND NOT isUuid(body.newSubscriptionPlanId):
        errors.push('newSubscriptionPlanId must be a valid UUID.')
    IF NOT trim(body.reason): errors.push('reason is required.')
    RETURN { valid: errors.empty, errors,
        clean: { newQuantity: body.newQuantity ? int(body.newQuantity) : undefined,
                 newSubscriptionPlanId: body.newSubscriptionPlanId, reason: trim(body.reason) } }

FUNCTION validateCancel(body):
    errors = []
    IF NOT trim(body.reason): errors.push('reason is required.')
    RETURN { valid: errors.empty, errors, clean: { reason: trim(body.reason) } }
```

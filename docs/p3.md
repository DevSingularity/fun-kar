## 1. Assumptions carried into this phase

1. **Cross-engine reuse follows the Phase 1 rule literally**: quotations never touches `products`/`price_lists`/`governance` tables directly — it calls `products.service.getById()`, `priceLists.service.resolve()`, and (new) `risk.service.resolveAllowedDiscount()` / `risk.service.evaluateQuoteRisk()`. This keeps the discount-limit formula defined in exactly one place (§6 below).
2. **`risk.service.js` gains one new export, `resolveAllowedDiscount(tier, categoryId)`.** Phase 2 built `evaluateQuoteRisk` as the only risk-engine entry point, but `quotation_items.allowed_discount_pct` is `NOT NULL` and must be populated the moment a line is added — before any `submit`. Rather than duplicate `MIN(tierLimit, categoryLimit ?? 100)` inside the quotations module, the risk engine (which already owns the governance-table reads) exposes this as a second pure function. `evaluateQuoteRisk` still **recomputes independently at submit time** rather than trusting the stored per-line snapshot — the snapshot is a display/UX convenience for the builder screen, never the authority (Rule 2, `plan.md`).
3. **A new `modules/approval` engine is introduced now, with no HTTP routes yet** — mirroring how `modules/risk` shipped route-less in Phase 2. `plan.md` §3.4 requires "create approval request if required" as a backend side effect of submit; that write belongs to the Approval Engine's own repository (architecture diagram), not to `quotations.repository`. Phase 4 adds `approval.routes.js` with the actual Approve/Reject/Return actions on top of this same repository.
4. **Quote-number generation uses a dedicated Postgres sequence** (`quotation_number_seq`, added via migration — a DB object, not a new logical table), formatted `Q-<YYYY>-<6-digit-seq>`. This is the only race-free way to satisfy the existing `quote_number` unique column without a read-then-write gap; the sequence is global (not reset per year) — the year in the string is cosmetic.
5. **Visibility (read + write) is role-scoped**: `SALES_REP` may only list/view/mutate quotations where `salesRepId == self`; `ADMIN` and `SALES_MANAGER` can act on any quotation. `FINANCE`/`OPERATIONS` get read access to any quotation (their Phase-4+ work — approval, deal health — needs company-wide visibility) but cannot create/edit/submit one, per the Problem Statement's role table (§3), which never gives them quotation-authoring duties.
6. **A quotation is only mutable (header edits, line-item CRUD, submit) while `status = DRAFT`.** Every other status is a downstream, engine-owned state (`PENDING_APPROVAL` → Approval Engine in Phase 4, `CONFIRMED`/`FULFILLING` → Fulfillment/Negotiation engines later). Attempting to mutate a non-`DRAFT` quotation is `409 INVALID_STATE`.
7. **`DELETE /quotations/:id` is a hard delete, restricted to `DRAFT`.** Unlike catalog resources, a draft quotation has no downstream references yet (`quotation_items` cascades), so there's nothing to protect by soft-deleting it — and once it leaves `DRAFT` it becomes immutable audit history, so delete is simply refused (`409`), not soft-flagged.
8. **Margin definition** (not specified numerically by `plan.md` beyond "Revenue − Estimated Cost = Margin"): revenue is **pre-tax, post-discount** (`subtotal − discountTotal`), since tax is a pass-through, not sales revenue. `estimatedMarginPct = margin / preTaxRevenue × 100`, `0` when pre-tax revenue is `0`. A derived (non-persisted) health label — `HEALTHY ≥ 20%`, `WATCH 10–20%`, `LOW_MARGIN < 10%` — is computed at read time only, per `plan.md` §3.3's bonus ("avoid fake AI language; show the actual calculation").
9. **Per-line audit logging is out of scope for this phase.** `plan.md` §A3's "all approvals, rejections, and edits must be logged" is read as governing *config* edits (built in Phase 2) and approval decisions (Phase 4) — logging every quantity/discount keystroke on a still-mutable draft would be noise, not evidence. The one audit event this phase does write is the `submit` state transition itself, since that's the moment a quote's commercial terms become fixed and reviewable.
10. **Item mutation and submit each lock the parent quotation row (`SELECT ... FOR UPDATE`) inside a transaction.** This is the single concurrency guard for the whole module: it serializes concurrent line-adds against each other (no lost-update on the aggregate totals) and serializes a late line-add against an in-flight `submit` (no line sneaking in after risk was evaluated).
11. **Pipeline cards are unpaginated per column** at current hackathon data volumes (Rule 5) — flagged as a scaling caveat, same posture Phase 2 took on offset/limit pagination generally.

### 4.1 `POST /quotations/:id/items` — the non-trivial case

- **Purpose:** price a product against the quotation's customer, snapshot the line, recompute quotation totals — all in one round trip, per `plan.md`'s "totals update, margin updates" requirement.
- **Body:** `{ productId, quantity, discountPct? }`.
- **Validation:** `productId` UUID; `quantity` positive integer; `discountPct` (default `0`) within `0–100`.
- **Idempotency:** not idempotent by convention — two identical calls add two lines (same posture as every other plain-create in this codebase).
- **Transaction boundary:** one transaction covers: lock quotation row → verify `DRAFT` → resolve product → resolve price → resolve allowed discount → insert `quotation_items` row → re-select all lines → recompute + write aggregate totals on `quotations`.
- **DB/service flow (no N+1):**
  1. `tx: SELECT * FROM quotations WHERE id=:id FOR UPDATE` (lock + ownership/status check in one read).
  2. `products.service.getById(productId)` (cross-engine service call) → `404` if missing/inactive.
  3. `priceLists.service.resolve({ customerId: quotation.customerId, productId })` → `{ customerPrice, priceSource, currency }`.
  4. `risk.service.resolveAllowedDiscount(customer.tier, product.categoryId)` → `allowedDiscountPct` (display snapshot only, per assumption 2).
  5. `quotations.calc.computeLineTotals({...})` → `{ discountAmount, taxAmount, lineTotal, estimatedCost }`.
  6. `tx.insert(quotationItems)`.
  7. `tx.select` all items for the quotation → `quotations.calc.computeQuotationTotals(items)` → `tx.update(quotations)` with the new aggregates + `lastActivityAt=now()`.
- **Concurrency:** the `FOR UPDATE` lock from step 1 serializes any second concurrent item-mutation or `submit` on the same quotation until this transaction commits — no lost update on the aggregate columns.
- **Rollback:** any failure (bad product, DB error) rolls back the whole transaction — no orphaned line without updated totals, or vice versa.
- **Success:** `201 { success:true, data:{ item, quotation:{ subtotal, discountTotal, taxTotal, grandTotal, estimatedMarginPct } } }`.
- **Errors:** `400 VALIDATION_FAILED`, `403 FORBIDDEN` (not owner), `404 NOT_FOUND` (quotation/product), `409 INVALID_STATE` (not `DRAFT`), `500`.
- **Performance:** 4 point lookups/service calls (all indexed PK/unique lookups, none per-row-looped) + 1 insert + 1 re-aggregation `SELECT`+`UPDATE` — flat cost regardless of line count except the final `SELECT` which is bounded by items-per-quote (small).

### 4.2 `POST /quotations/:id/submit` — the automatic approval trigger

- **Purpose:** implement §3.4's exact sequence — validate → calculate discounts/margin (already true of the stored aggregates) → calculate risk → determine approval chain → create approval request if required → change status.
- **Idempotency:** retry-safe by design — see step 2 below; a repeated call after the first success returns the already-resolved state instead of erroring or double-creating an approval request.
- **Transaction boundary:** one transaction: lock quotation → validate → call risk engine (read-only) → write quotation status/risk snapshot → conditionally write `approval_requests` (via the Approval Engine) → write one `audit_logs` row.
- **DB/service flow:**
  1. `tx: SELECT * FROM quotations WHERE id=:id FOR UPDATE`.
  2. `IF quotation.status != 'DRAFT'`: if it's already `PENDING_APPROVAL` or `APPROVED`, return the current state as a `200` (idempotent no-op — assumption 10/idempotency); any other status is `409 INVALID_STATE`.
  3. `IF quotation has zero items`: `400 EMPTY_QUOTATION`.
  4. `risk.service.evaluateQuoteRisk(quotationId)` (unchanged Phase-2 contract, reads outside the write path but inside the same DB transaction/connection for a consistent snapshot).
  5. `newStatus = riskResult.requiredApprovalLevel == 'NONE' ? 'APPROVED' : 'PENDING_APPROVAL'`.
  6. `tx.update(quotations)` — `status`, `blendedRiskScore`, `requiredApprovalLevel`, `submittedAt=now()`, and `confirmedAt` untouched.
  7. `IF newStatus == 'PENDING_APPROVAL'`: `approval.service.createIfRequired(tx, quotationId, riskResult)`.
  8. `tx.insert(auditLogs)` — `entityType='QUOTATION'`, `action = newStatus=='APPROVED' ? 'AUTO_APPROVED' : 'SUBMITTED_FOR_APPROVAL'`, `oldValue:{status:'DRAFT'}`, `newValue:{status:newStatus, blendedRiskScore, requiredApprovalLevel}`.
- **Concurrency:** the row lock from step 1 means two concurrent `submit` calls (e.g. a double-click) serialize — the second sees the already-updated status in step 2 and short-circuits to the idempotent branch instead of racing to create two approval requests. The `approval_requests` partial unique index (`one_pending_per_quotation`) is the second, database-level backstop.
- **Rollback:** any failure — including the approval-insert hitting the partial unique index — rolls back status/risk-snapshot/audit-log together; the quotation is never left `PENDING_APPROVAL` without a matching request, or vice versa.
- **Success:** `200 { success:true, data:{ quotation, riskEvaluation, approvalRequest } }` (`approvalRequest: null` when auto-approved).
- **Errors:** `400 EMPTY_QUOTATION`, `403 FORBIDDEN`, `404 NOT_FOUND`, `409 INVALID_STATE`, `500`.
- **Performance:** `evaluateQuoteRisk` is already a single batched, no-N+1 read (Phase 2); this endpoint adds at most one more insert (`approval_requests`) and one audit-log insert — all indexed, single-row.

### 4.3 `GET /quotations/pipeline`

- **Purpose:** power the Kanban view (§3.5) — 7 columns: `DRAFT, PENDING_APPROVAL, APPROVED, UNDER_NEGOTIATION, CONFIRMED, FULFILLING, COMPLETED` (deliberately excludes `REJECTED`/`CANCELLED`, which aren't part of the plan's named pipeline).
- **DB flow (single query, no N+1):** one `SELECT` over `quotations` (joined to `customers` for name) `WHERE status IN (7 statuses) AND [salesRepId = self, if SALES_REP]`, grouped in application code by `status` into the 7 fixed columns (empty columns still render).
- **Success:** `200 { success:true, data:{ columns:[{ status, label, count, totalAmount, quotations:[{id, quoteNumber, customerName, grandTotal, lastActivityAt}] }, ...] } }`.
- **Performance:** one indexed (`quotations_status_idx`) query; grouping happens in memory over an already-small result set.

**File: `server/src/modules/quotations/quotations.calc.js`** *(pure — no DB, no I/O; unit-testable in isolation)*
```
FUNCTION computeLineTotals({ unitPrice, quantity, discountPct, taxRatePct, estimatedCostPerUnit }):
    grossAmount   = unitPrice * quantity
    discountAmount = round2(grossAmount * discountPct / 100)
    taxableAmount  = grossAmount - discountAmount
    taxAmount      = round2(taxableAmount * taxRatePct / 100)
    lineTotal      = taxableAmount + taxAmount
    estimatedCost  = round2(estimatedCostPerUnit * quantity)
    RETURN { discountAmount, taxAmount, lineTotal, estimatedCost }

FUNCTION computeQuotationTotals(items):
    subtotal      = sum(items, i => i.unitPrice * i.quantity)
    discountTotal = sum(items, i => i.discountAmount)
    taxTotal      = sum(items, i => i.taxAmount)
    grandTotal    = sum(items, i => i.lineTotal)
    totalCost     = sum(items, i => i.estimatedCost)

    preTaxRevenue = subtotal - discountTotal
    marginAmount  = preTaxRevenue - totalCost
    marginPct     = preTaxRevenue > 0 ? round2(marginAmount / preTaxRevenue * 100) : 0

    RETURN { subtotal: round2(subtotal), discountTotal: round2(discountTotal),
             taxTotal: round2(taxTotal), grandTotal: round2(grandTotal),
             estimatedMarginPct: marginPct, marginAmount: round2(marginAmount) }

FUNCTION marginHealthLabel(marginPct):
    IF marginPct >= 20: RETURN 'HEALTHY'
    IF marginPct >= 10: RETURN 'WATCH'
    RETURN 'LOW_MARGIN'
```

        items, latestApprovalRequest,
        marginHealth: calc.marginHealthLabel(marginPct)
    }

FUNCTION list(query, auth):
    { page, pageSize, offset, sortBy, sortDir } = parseListQuery(query, {
        allowedSortColumns:['createdAt','grandTotal','lastActivityAt'], defaultSort:'lastActivityAt' })
    scopedSalesRepId = auth.role == 'SALES_REP' ? auth.userId : query.salesRepId OR null
    { rows, total } = await repo.list({ ...query, salesRepId: scopedSalesRepId, offset, limit: pageSize, sortBy, sortDir })
    RETURN { items: rows, meta: buildMeta({page,pageSize,total}) }

FUNCTION pipeline(auth):
    scopedSalesRepId = auth.role == 'SALES_REP' ? auth.userId : null
    rows = await repo.listForPipeline({ salesRepId: scopedSalesRepId })
    COLUMNS = [
        {status:'DRAFT', label:'Draft'}, {status:'PENDING_APPROVAL', label:'Pending Approval'},
        {status:'APPROVED', label:'Approved'}, {status:'UNDER_NEGOTIATION', label:'Under Negotiation'},
        {status:'CONFIRMED', label:'Confirmed'}, {status:'FULFILLING', label:'Fulfillment'},
        {status:'COMPLETED', label:'Completed'}
    ]
    RETURN { columns: COLUMNS.map(c => {
        cards = rows.filter(r => r.status == c.status)
        RETURN { ...c, count: cards.length, totalAmount: sum(cards, r=>r.grandTotal), quotations: cards }
    })}

FUNCTION create(payload, auth):
    IF NOT await customerExists(payload.customerId): THROW NotFoundError('Customer')
    salesRepId = payload.salesRepId AND ['ADMIN','SALES_MANAGER'].includes(auth.role)
        ? payload.salesRepId
        : auth.userId
    IF payload.salesRepId AND salesRepId != payload.salesRepId:
        THROW ForbiddenError('Only a Manager or Admin can assign a quotation to another rep.')

    RETURN db.transaction(async (tx) => {
        quoteNumber = await nextQuoteNumber(tx)
        RETURN repo.insertHeader(tx, {
            quoteNumber, customerId: payload.customerId, salesRepId,
            promisedDeliveryDate: payload.promisedDeliveryDate, status:'DRAFT'
        })
    })

FUNCTION update(id, payload, auth):
    quotation = await getOwnedDraft(id, auth)     // throws 404/403/409 as appropriate
    IF payload.salesRepId AND !['ADMIN','SALES_MANAGER'].includes(auth.role):
        THROW ForbiddenError('Only a Manager or Admin can reassign a quotation.')
    IF payload.salesRepId AND NOT await repIsSalesCapable(payload.salesRepId): THROW NotFoundError('Sales rep')
    RETURN repo.applyAggregateTotals(db, id, payload)   // reuses the same set+lastActivityAt path

FUNCTION remove(id, auth):
    RETURN db.transaction(async (tx) => {
        quotation = await repo.lockById(tx, id)
        IF NOT quotation: THROW NotFoundError('Quotation')
        assertOwnership(quotation, auth)
        IF quotation.status != 'DRAFT': THROW ConflictError('INVALID_STATE', 'Only a draft quotation can be deleted.')
        await repo.deleteHeader(tx, id)     // cascades quotation_items
        RETURN { deleted: true }
    })

// --- Items ---

FUNCTION getOwnedDraft(tx, id, auth):
    quotation = await repo.lockById(tx, id)
    IF NOT quotation: THROW NotFoundError('Quotation')
    assertOwnership(quotation, auth)
    IF quotation.status != 'DRAFT': THROW ConflictError('INVALID_STATE', 'Quotation is no longer editable.')
    RETURN quotation

FUNCTION recomputeAndPersistTotals(tx, quotationId):
    itemsJoined = await repo.findItemsJoined(quotationId)      // re-read inside same txn/lock
    totals = calc.computeQuotationTotals(itemsJoined.map(r => r.item))
    RETURN repo.applyAggregateTotals(tx, quotationId, totals)

FUNCTION addItem(quotationId, payload, auth):
    RETURN db.transaction(async (tx) => {
        quotation = await getOwnedDraft(tx, quotationId, auth)

        product = await productsService.getById(payload.productId)   // 404 if missing (service throws)
        IF NOT product.isActive: THROW ConflictError('PRODUCT_INACTIVE', 'This product is no longer sellable.')

        price = await priceListsService.resolve({ customerId: quotation.customerId, productId: product.id })
        allowedDiscountPct = await riskService.resolveAllowedDiscount(quotation.customerTier, product.categoryId)

        lineCalc = calc.computeLineTotals({
            unitPrice: price.customerPrice, quantity: payload.quantity, discountPct: payload.discountPct,
            taxRatePct: product.taxRate, estimatedCostPerUnit: product.estimatedCost
        })

        item = await repo.insertItem(tx, {
            quotationId, productId: product.id, quantity: payload.quantity,
            unitPrice: price.customerPrice, allowedDiscountPct, discountPct: payload.discountPct,
            ...lineCalc
        })
        updatedQuotation = await recomputeAndPersistTotals(tx, quotationId)
        RETURN { item, quotation: updatedQuotation }
    })

FUNCTION updateItem(quotationId, itemId, payload, auth):
    RETURN db.transaction(async (tx) => {
        quotation = await getOwnedDraft(tx, quotationId, auth)
        existing = await repo.findItemById(tx, itemId)
        IF NOT existing OR existing.quotationId != quotationId: THROW NotFoundError('Quotation item')

        merged = { quantity: payload.quantity ?? existing.quantity, discountPct: payload.discountPct ?? existing.discountPct }
        lineCalc = calc.computeLineTotals({
            unitPrice: existing.unitPrice, quantity: merged.quantity, discountPct: merged.discountPct,
            taxRatePct: existing.taxRatePctSnapshot, estimatedCostPerUnit: existing.estimatedCost / existing.quantity
        })
        // NOTE: unitPrice/allowedDiscountPct are NOT re-resolved on update — they were snapshot at add-time;
        // re-pricing on every quantity tweak would silently change terms the rep already saw. A price/tier
        // change is picked up only if the line is removed and re-added.
        item = await repo.updateItem(tx, itemId, { ...merged, ...lineCalc })
        updatedQuotation = await recomputeAndPersistTotals(tx, quotationId)
        RETURN { item, quotation: updatedQuotation }
    })

FUNCTION removeItem(quotationId, itemId, auth):
    RETURN db.transaction(async (tx) => {
        quotation = await getOwnedDraft(tx, quotationId, auth)
        existing = await repo.findItemById(tx, itemId)
        IF NOT existing OR existing.quotationId != quotationId: THROW NotFoundError('Quotation item')
        await repo.deleteItem(tx, itemId)
        updatedQuotation = await recomputeAndPersistTotals(tx, quotationId)
        RETURN { deleted: true, quotation: updatedQuotation }
    })

// --- Submit (§3.4) ---

FUNCTION submit(quotationId, auth):
    RETURN db.transaction(async (tx) => {
        quotation = await repo.lockById(tx, quotationId)
        IF NOT quotation: THROW NotFoundError('Quotation')
        assertOwnership(quotation, auth)

        IF quotation.status == 'PENDING_APPROVAL' OR quotation.status == 'APPROVED':
            RETURN { quotation, riskEvaluation: null, approvalRequest: await repo.findLatestApprovalRequest(quotationId), idempotentReplay: true }
        IF quotation.status != 'DRAFT':
            THROW ConflictError('INVALID_STATE', 'Only a draft quotation can be submitted.')

        itemsJoined = await repo.findItemsJoined(quotationId)
        IF itemsJoined.length == 0: THROW ValidationError(['Cannot submit a quotation with no line items.'])

        riskResult = await riskService.evaluateQuoteRisk(quotationId)   // read-only, batched, no N+1 (Phase 2)
        newStatus = riskResult.requiredApprovalLevel == 'NONE' ? 'APPROVED' : 'PENDING_APPROVAL'

        updatedQuotation = await repo.applySubmitResult(tx, quotationId, {
            status: newStatus, blendedRiskScore: riskResult.blendedRiskScore,
            requiredApprovalLevel: riskResult.requiredApprovalLevel
        })

        approvalRequest = newStatus == 'PENDING_APPROVAL'
            ? await approvalService.createIfRequired(tx, quotationId, riskResult)
            : null

        await repo.insertAuditLog(tx, {
            actorId: auth.userId, entityType:'QUOTATION', entityId: quotationId,
            action: newStatus=='APPROVED' ? 'AUTO_APPROVED' : 'SUBMITTED_FOR_APPROVAL',
            oldValue: { status:'DRAFT' },
            newValue: { status:newStatus, blendedRiskScore: riskResult.blendedRiskScore, requiredApprovalLevel: riskResult.requiredApprovalLevel }
        })

        RETURN { quotation: updatedQuotation, riskEvaluation: riskResult, approvalRequest, idempotentReplay: false }
    })
